# NHSM Helper

A chatbot for the NHSM school. Students ask questions in English, French, Arabic
or Algerian Darija and get answers grounded in real school information.

**Live demo:** https://nhsm-helper.netlify.app

## How it works

Every question goes through a retrieval augmented generation (RAG) pipeline:

| # | Stage | Where | What it does |
|---|-------|-------|--------------|
| 0 | **Greeting shortcut** | `chatController.isGreeting()` | "hi", "merci", "salam" → instant reply, no LLM and no database call |
| 1 | **Conversational condensation** | `aiService.condenseConversationalQuery()` | "and for SESA?" becomes "What is the SESA specialty?" using the chat history |
| 2 | **Query rewriting** | `aiService.rewriteQueryForSearch()` | Expands the question into English + French keywords for lexical search |
| 3a | **Vector search** | `knowledgeBaseService._vectorSearch()` | In-memory cosine similarity over 324 embeddings and their paraphrases |
| 3b | **Keyword search** | `knowledgeBaseService._keywordSearch()` | MongoDB regex with singular/plural variants |
| 4 | **RRF fusion** | `_reciprocalRankFusion()` | Merges both rankings by *rank*, so the two score scales never have to be reconciled |
| 5 | **Reranking** | `rerankService.rerank()` | Cohere cross-encoder; skipped when its top score is below 0.05, where it carries no signal |
| 6 | **Generation** | `aiService.generateResponseStream()` | Groq, streamed, in the detected language |

This keeps answers grounded in the school's actual information instead of
whatever the model happens to guess. When retrieval comes back empty, the model
is explicitly instructed to say so rather than fill the gap.

### Multi-query paraphrase indexing

On top of its main embedding, every document stores **5 embedded paraphrases**
(2 French, 2 English, 1 Darija) generated by Llama. At search time the score is
the **maximum** similarity across those 6 vectors, so one answer becomes
reachable through every way a student might phrase the question.

### Why not Atlas `$vectorSearch`?

At 324 documents, in-memory cosine similarity takes under a millisecond and
about 16 MB of RAM. An Atlas index would add a network round trip per query for
no measurable gain. `scripts/create-vector-indexes.js` is there if the corpus
ever passes ~50k documents; below that it is not worth it.

## Stack

- **API:** Node.js, Express
- **Database:** MongoDB Atlas with Mongoose — 9 collections, 324 documents
- **LLM:** Llama 3.1 8B via the Groq API
- **Retrieval:** Cohere `embed-multilingual-v3.0` + `rerank-multilingual-v3.0`
- **Hardening:** Helmet headers, per-IP rate limiting, CORS allowlist, 64 kb body cap

## Getting started

```sh
npm install
cp .env.example .env   # add your MongoDB URI, Groq and Cohere keys
npm run dev
```

### Environment variables

| Variable | Required | Default | Purpose |
|----------|----------|---------|---------|
| `MONGO_URI` | yes | — | MongoDB Atlas connection string |
| `GROQ_API_KEY` | yes | — | Answer generation and query rewriting |
| `COHERE_API_KEY` | yes | — | Embeddings and reranking. Without it the bot falls back to keyword-only search |
| `PORT` | no | `5000` | Render injects this automatically |
| `NODE_ENV` | no | `development` | `production` hides detailed error messages |
| `ALLOWED_ORIGINS` | no | — | Extra CORS origins, comma separated |
| `RATE_LIMIT_MAX` | no | `30` | Requests per IP per 15 minutes |
| `RATE_LIMIT_LONG_MAX` | no | `10` | Messages over 200 characters per 5 minutes |
| `SKIP_PUBLIC_DNS` | no | — | Set to `1` to stop forcing the 8.8.8.8 resolver |

> **NAT warning:** on the campus network every student may share one public IP
> and therefore one quota. Raise `RATE_LIMIT_MAX` if legitimate users get
> blocked.

> **Groq free tier:** 6000 tokens per minute. The prompt builder caps context at
> ~7000 characters and shrinks each source as their count grows, so a single
> "list every professor" question can no longer exhaust the whole minute.

## Scripts

```sh
npm run embed        # embed documents that don't have a vector yet
npm run paraphrase   # generate 5 paraphrases + embeddings per document
npm run inspect      # print a sample of every collection
npm run eval         # evaluation suite (40+ cases, scored 0-100)
```

All of them accept `--dry-run`, `--force` and `--col=<collection>`.

After a reindex the server picks up new vectors **on its own** within 10 minutes
(cache TTL) — no restart needed.

## Evaluation

`eval-chatbot.js` scores 43 questions across all nine collections on six
metrics. Latest run — 43/43 played, **94/100**, 37 A, 5 B, 1 C, **0 failures**:

| Metric | Score |
|--------|-------|
| DB Retrieval | 18.6/20 (93%) |
| Source Quality | 18.0/20 (90%) |
| Language Match | 15.0/15 (100%) |
| Completeness | 14.9/15 (99%) |
| Anti-hallucination | 15.0/15 (100%) |
| Relevance | 12.6/15 (84%) |

The three retrieval misses are known: one targets `MathTip`, whose collection is
empty, and two reach a neighbouring collection holding equivalent content
(pomodoro also lives in `wellnesses`, online resources also in `studytips`).

The suite paces itself at 25s per test to stay under the Groq free tier's 6000
tokens/minute, retries on quota errors and **excludes** quota-blocked tests from
the average — scoring them zero would measure the rate limit rather than answer
quality. Override with `EVAL_DELAY_MS` on a paid tier.

### A note on relevance gating

Do not gate retrieval on the rerank score. Measured on this corpus, a legitimate
Derdja question (« وش هوما تخصصات لي كاينين ف ليكول ») scores **0.0004** while an
off-topic French one (apple pie recipe) scores **0.0065** — the distributions
overlap, and a 0.008 threshold dropped a real test from 80/100 to 45/100. Cohere's
reranker orders results well but cannot judge absolute relevance in Algerian
Derdja. Cosine similarity separates the same sample correctly (off-topic peaks at
0.49, relevant bottoms at 0.55) but by only 12%, which is too thin to deploy
without a much larger, Derdja-heavy calibration set.

## Project structure

```
src/
  app.js           Express app setup, security middleware
  server.js        entry point, Mongo connection, cache warm-up
  config/          environment configuration
  controllers/     chat request handling, greeting shortcut
  middleware/      rate limiting, validation, error handling
  models/          Mongoose schemas for the nine collections
  services/        RAG pipeline: rewriting, retrieval, reranking, generation
scripts/           embedding, paraphrase and evaluation tools
public/            static chat UI (deployed to Netlify)
```

## Deployment

**Render (API)** — build `npm install`, start `npm start`. Set `MONGO_URI`,
`GROQ_API_KEY`, `COHERE_API_KEY` and `NODE_ENV=production`. The free tier sleeps
after 15 minutes idle, so the first request can take ~30 s.

**Netlify (UI)** — publish the `public/` folder. The backend URL is picked at
runtime in `index.html` (`BACKEND_URL`); update it if the Render address changes.

**Atlas** — allow Render's outbound IPs under *Network Access*.
